Built-in Tools

Grok can read files, edit files, run commands, and more. You describe the goal; Grok chooses tools—and often asks permission.

Know what a “turn” is from First Session

What is a “tool” here?

When people say ChatGPT “can’t touch my files,” they mean it only replies with text. Grok has tools: built-in abilities to act on your computer and the internet. You usually do not type tool names. You describe a goal; Grok chooses tools.

Still, knowing the toolkit helps you write better goals (“run the tests” implies the shell tool; “edit only this file” implies file tools).

Permissions reminder

Many tools pause for your OK. That is normal. Reading is usually freer than writing or running commands.

How to aim Grok at the right tools

Say the verification command

“After changes, run npm test.” Forces shell use and a success definition.

Limit the blast radius

“Only edit files under css/. Do not touch server code.”

Ask for explore first

“List the files involved and summarize; wait for my OK before editing.”

Background long jobs

“Start the dev server in the background, then keep working on the UI.”

Try this

In ~/tmp/grok-lab ask: “Search this folder for any .js files, list their names, and do not edit anything.” You should see search/list behavior without file changes.
