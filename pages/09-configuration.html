Configuration

You can ignore most settings at first. When you need them: /settings, or a config file—explained simply.

Optional—read when you want themes or defaults

You can ignore config at first

Grok works with defaults. Change settings only when you have a reason (theme hurts your eyes, you want Vim keys, you need a different default model).

Where settings live

  1. Easiest: inside Grok, run /settings and click/toggle options.
  2. Advanced: edit a text file named config.toml in your Grok home folder: ~/.grok/config.toml.

~ means your user home directory. On Mac/Linux that is often /Users/you or /home/you. The file uses TOML: simple key = value settings grouped under headers like [ui].

Precedence (who wins if settings conflict)

Command-line flags beat environment variables beat config.toml beat built-in defaults. You rarely need this until something “won’t stick.”

Examples you might actually change

# ~/.grok/config.toml  (create the file if missing)
[ui]
vim_mode = false
# permission_mode = "ask"

[models]
# default = "grok-4.5"

[session]
auto_compact_threshold_percent = 85

After editing, restart Grok so settings reload (unless the UI already applied them live).

Themes

Run /theme and arrow through previews. Minimal mode uses your terminal’s colors instead of fancy themes.

Models

A model is the AI engine behind answers. List them with grok models in a normal terminal, or /model inside Grok. Stick to defaults until you have a reason to switch (speed, cost, special features).

Safe practice

Only change theme via /theme today. Avoid hand-editing config until you are comfortable recovering from a typo (broken config can confuse startup—rename the file aside if that happens).
