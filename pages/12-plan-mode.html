Plan Mode

For big or unclear work: Grok writes a plan first. You approve it. Then coding starts.

You have finished a few normal edit sessions

The problem

If you say “add multiplayer” without a plan, Grok might start editing random files in a direction you hate. Plan mode freezes product coding and forces a written approach first.

What happens in plan mode

  1. Grok reads your project (explore).
  2. It writes a plan document (approach, files, how to test).
  3. It may ask you clarifying questions.
  4. You review the plan: approve, request changes, comment, or quit.
  5. Only after approval does normal implementation begin.

While planning, Grok should not edit your real game/app files—only the plan file.

How to turn it on

  • Type /plan and Enter, then describe the work—or /plan add save games to disk.
  • Or press Shift+Tab until the UI shows Plan mode (watch the mode indicator).

Approval keys (when the plan preview is open)

KeyMeaning
aApprove — start building
sRequest changes — type what to fix in the plan
cComment on a line
qQuit plan mode without building

Reopen later with /view-plan.

Use plan mode

  • New systems (auth, saves, netcode)
  • Big refactors
  • Several valid architectures

Skip plan mode

  • Typos and copy changes
  • One obvious bug in one file
  • Pure formatting

Lab

  1. In a throwaway or practice project, type /plan and Enter.
  2. Describe a medium task (example: “add a restart button and a win message”).
  3. Wait for the plan preview. Scroll it. Press q to quit or a only if you want Grok to build it.
  4. Confirm you can reopen guidance later with /view-plan if a plan was saved.
Done when

You can enter plan mode, read a plan preview, and choose approve / request changes / quit without guessing keys. You know plan mode is for big or unclear work—not for typos.
