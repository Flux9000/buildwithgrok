Subagents & Personas

Subagents are helper chats with their own notes. Use them to research or work without flooding the main chat.

You are comfortable with one main session

Analogy

Your main Grok chat is the lead engineer. A subagent is a teammate with a fresh notepad. They investigate or implement a side task, then report a summary back so the lead’s notepad does not overflow.

Common helper types

Explore

Reads and searches; aimed at understanding. Good for “map how inventory works.”

Plan

Designs an approach without editing product code.

General-purpose

Full helper that can implement when delegated.

You usually do not manually spawn these at first—Grok does when the task is large. You can also ask in English: “Use an explore pass first; do not edit until you summarize findings.”

Personas

A persona is a tone/behavior overlay (“be extremely concise,” “always cite file paths”). Managed via /personas. Optional polish, not required to ship software.

Agents modal

/config-agents lets advanced users define custom agent setups. Skip until defaults feel limiting.

Phrase to try

Copy this into Grok when a task is large: “First explore the codebase read-only and list the files involved. Wait for my OK before changing anything.”

Lab

  1. In a real project folder, start Grok and send the phrase above (or: “Use an explore pass first; do not edit until you summarize findings.”).
  2. Read the summary. Confirm no product files were edited yet (or only exploration happened).
  3. Only then send: “OK—implement the smallest fix based on that summary” or stop if you were only practicing exploration.
Done when

You can explain: main session = lead chat; subagent = helper with its own notes; explore helpers should not edit until you say so. You have tried one explore-first prompt.
